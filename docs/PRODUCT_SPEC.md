# DomesticTrip — PRODUCT_SPEC

국내 관광지를 찾아 여행 날짜별로 정리하는 여행 일정 앱이다. 방문 시간이나 이동 경로까지 계획하기보다는, **어느 날 어디를 어떤 순서로 방문할지**에 집중한다.

## 1. 화면 구성과 이동

| 화면 | 주요 기능 |
| --- | --- |
| Home | 진행 중인 여행과 다음 여행을 보여주고, 새 여행을 만들 수 있다. |
| Explore | 관광지를 검색하거나 카테고리별로 살펴본다. |
| My Trips | 예정·진행 중·지난 여행을 모아 보고 수정·삭제한다. |
| Settings | 앱 언어를 한국어 또는 영어로 변경한다. |
| Create / Edit Trip | 여행 제목과 출발일·종료일을 달력으로 선택한다. |
| Trip Detail | Day별 장소를 확인하고 추가·제거·이동·순서 변경을 한다. |
| Place Detail | 관광지 사진·설명·주소를 보고 여행에 추가한다. |

하단에는 `Home / Explore / My Trips / Settings` 네 개의 탭을 둔다. 상세 화면은 해당 탭에서 진입한다.

- **Explore에서 추가:** 관광지 상세 → 여행 선택 → Day 선택 → 추가. 추가한 뒤에도 탐색을 이어갈 수 있다.
- **Trip Detail에서 추가:** 이미 선택한 여행과 Day를 유지한 상태로 관광지만 고른다.
- 장소의 방문 **시간은 입력하지 않는다.** Day 안의 방문 순서만 관리한다.

## 2. 데이터 저장 및 상태 관리

데이터를 모두 같은 곳에 보관하지 않는다. **오래 남아야 하는 정보인지, 인터넷에서 가져오는 정보인지, 현재 화면에서만 잠깐 필요한 값인지**에 따라 나눈다.

| 구분 | 맡는 역할 | DomesticTrip에서의 예시 |
| --- | --- | --- |
| **SQLite** | 기기에 데이터를 저장한다. 앱을 껐다 켜도 남는다. | 여행 제목·날짜, Day별 장소와 방문 순서, 사용자가 선택한 앱 언어 |
| **TanStack Query** | TourAPI 데이터를 불러오고 잠시 캐시한다. 필요할 때 새로 요청한다. | 관광지 검색 결과, 관광지 상세 정보 |
| **컴포넌트 상태** | 지금 보고 있는 화면에서만 쓰는 값을 관리한다. | 선택한 Day, 열려 있는 모달, 작성 중인 입력값 |

예를 들어 관광지를 검색할 때의 결과는 TanStack Query가 관리한다. 사용자가 그 관광지를 **여행 일정에 추가하는 순간**, 장소 이름·주소·이미지 등 화면 표시에 필요한 정보와 방문 순서를 SQLite에 저장한다. 그래서 TourAPI에 연결할 수 없어도 **이미 저장한 여행 일정은 열어볼 수 있다.**

현재 Zustand는 사용하지 않는다. 선택한 Day와 모달 등의 임시 값은 컴포넌트 상태로 관리한다. SQLite에는 `trips`, `trip_places`, `app_settings`를 두며, 장소의 Day는 1부터 시작하는 `day_number`로 저장한다. 실제 방문 날짜는 출발일에서 계산하므로 날짜를 바꿔도 장소는 원래 Day 번호에 남는다. 기간 단축으로 사라지는 Day에 장소가 있으면 저장을 막고 먼저 정리하도록 안내한다.

## 3. 다국어 및 접근성

- 한국어와 영어를 지원한다. 첫 실행에는 기기 언어를 참고하고, Settings에서 선택한 언어가 있으면 그 설정을 우선한다.
- 메뉴·버튼·안내 문구는 번역 리소스로 관리한다. 사용자가 작성한 여행 제목이나 관광지 원문을 임의로 번역하지 않는다.
- 날짜 표시는 선택 언어에 맞추되 여행 날짜의 기준은 한국 시간(`Asia/Seoul`)으로 통일한다.
- 글자 크기 확대, TalkBack/VoiceOver 읽기, 충분한 터치 영역과 색상 대비를 고려한다.
- 달력 선택과 장소 순서 변경은 스크린 리더 사용자도 조작할 수 있어야 한다.

## 4. 디자인 시스템

화면마다 비슷한 UI를 다시 만들지 않도록 공통 기준을 둔다.

- **디자인 토큰:** 색상, 글자 크기, 간격, 모서리 둥글기 등
- **공통 컴포넌트:** Button, Card, Dialog, EmptyState, PageHeading 등
- **기능별 컴포넌트:** TripCard, TripPlaceCard, TripDayPicker, TripDatePicker 등

실제로 여러 곳에서 쓰는 요소부터 공통화한다. 아직 사용하지 않는 컴포넌트까지 미리 만들지는 않는다.

## 5. 안정성과 성능

- 관광지 조회 중에는 로딩·빈 결과·오류를 구분해 보여주고, 실패하면 다시 시도할 수 있게 한다.
- 네트워크 오류나 앱 재실행으로 저장한 여행과 방문 순서가 사라지지 않아야 한다.
- 검색 요청이 지나치게 반복되지 않도록 캐싱, 입력 지연 처리, 페이지네이션을 활용한다.
- 관광지 목록에서 이미지 로딩이나 스크롤이 느려진다면 원인을 확인한 뒤 개선한다.
- 성능 개선은 가능하면 **변경 전·후를 같은 조건에서 비교**한다. 측정하지 않은 개선 효과를 수치로 표현하지 않는다.
